# Mac の layer 1 以上で割り当ての無いキーを、割り当てなしにする

状態: 採用

2026-09-28 に、layer 1 以上で設定していないキーを割り当てなしにしたいという要望を受けて決めた。

## 背景

ADR 0049 の生成器は、layer 1 以上の末尾に `___ _` を置いていた。
layer 1 以上で書かれていないキーは、layer 0 の割り当て（無ければ素通し）へ落ちる。

- Fact: `_` は下の layer の action を使う。layer を押している間も、その layer に書いていない文字キーは layer 0 の文字を出す
- Fact: kanata の `XX` は何も出さない action で、`deflayermap` の `___` は書かれていないキーすべてを指す

Cornix LP は Vial の `KC_TRNS` を明示しない限り下の layer へ落ちないため、Mac の挙動は Cornix と違っていた。

## 選択肢

1. layer 1 以上の末尾を `___ XX` にし、書かれていないキーを割り当てなしにする
2. 現状のまま下の layer へ落とし、無効にしたいキーへ個別に `KC_NO` を書く

## 決定

案 1 を採る。
利用者が選んだ。

- layer 1 以上の末尾は `___ XX` にする
- layer 1 以上の `KC_TRNS` は `_` と書き、明示したキーだけ下の layer へ落とす
- layer 0 と同値のキーも layer 1 以上へ書く。落ちなくなったため、省くと割り当てなしになる
- layer 0 は変えない。割り当ての無いキーは `process-unmapped-keys` で素通しする
- UI は layer 1 以上の割り当ての無いキーを素通しと呼ばず、「割り当てなし」と `—` で出す

## 理由

- **押している layer に書いたキーだけが効く。** 書いていないキーから layer 0 の文字が漏れない
- **Cornix と同じ規則になる。** 下の layer へ落とすのは `KC_TRNS` を書いたときだけになる

## 影響

- 既存の `mac-keyboard.<layout>.yaml` で、layer 1 以上が layer 0 への落下を前提にしていたキーは、次の適用から何も出さなくなる。必要なら `KC_TRNS` を書く
- layer 1 以上では、削除と `KC_NO` の挙動が同じになる。削除と `KC_NO` が別のセマンティクスになるのは layer 0 だけである（ADR 0022）
