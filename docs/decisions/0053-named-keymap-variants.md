# キーマップは名前を付けた別ファイルで保持し、切り替えは適用対象への書き戻しにする

状態: 採用

2026-10-11 に、利用者の「キーマップを保持して切り替えたい」という要望への形を決めた。\
workspace には既に手でコピーした `mac-keyboard.ansi.before-home-row-shift.yaml` があり、
配置の規則と導線が無いまま運用が始まっていた。

## 背景

キーマップを試行するとき、戻れる地点を名前で残し、あとで行き来したい。\
対象は Cornix の `keymap.yaml` と Mac の `mac-keyboard.<layout>.yaml` の両方である。

CLI の `mac apply`、ローカルサーバーの適用 API、kanata の再起動経路（ADR 0028・0034・0049）は、
固定名の 1 ファイルを読む前提で組まれている。\
Web UI は編集のたびにその固定名へ保存する（ADR 0038）。

## 選択肢

1. 適用対象は固定名のまま、保持は同じ directory に `keymap.<name>.yaml` /
   `mac-keyboard.<layout>.<name>.yaml` として並べ、切り替えは保持の内容を固定名へ書き戻す
2. すべてを名前付きファイルにし、`keysync/` 配下に「今どれを使うか」を記録する選択ファイルを置く
3. 1 ファイルの中に名前付きのセクションを持つ（schema を上げる）

## 決定

案 1 を採る。

- **適用対象の名前は変えない。** CLI、サーバー、kanata の経路は無変更で済む
- **保持は同じ directory に名前を埋めたファイルで持つ。** 名前は小文字の英数字とハイフンだけ（64 文字まで）。
  `.` を含めないので、ファイル名の `.` 区切りから配列と名前を一意に切り出せる
- **切り替えは、現在の内容がどれかの保持と一致しているときだけ行う。** 一致は正規形（parse して serialize した
  テキスト）で比べ、コメントや並び順の違いは同じ内容とみなす。一致しないときは落とし、先に名前を付けさせる
- **切り替え先は parse を通してから書く。** 壊れたファイルや別配列のファイルを適用対象へ写さない
- **削除できるのは保持だけ。** サーバーの `remove` も適用対象を拒む
- **切り替えは適用ではない。** 適用対象のファイルが変わるだけで、実機や kanata への反映は従来どおり人間が
  差分を確かめて行う
- 導線は Web UI の「ファイル」パネルと、CLI の `keysync keymaps …` / `keysync mac keymaps …` の両方に置く

## 理由

- **案 1 は読む側を一切変えない。** 案 2 は選択ファイルを読む経路を CLI・サーバー・UI の 3 か所に足し、
  選択ファイルと実体の食い違いという新しい故障を増やす。Git の履歴にも「どれを使っていたか」が
  固定名の diff としてそのまま残る
- **案 3 は ADR 0027 が退けた理由と同じ。** `parse` / `serialize` / `validate` / `generate` のすべてに波及する
- **一致を要求するのは、未保持の編集を黙って捨てないため。** Web UI は編集のたびに固定名へ保存するので、
  「現在の内容」は常にディスクにある。切り替えで消えるのはディスク上のその 1 ファイルだけで、
  どの保持とも一致していれば失うものは無い
- **正規形で比べるのは、手で書いたコメントで切り替えを止めないため。** ADR 0034 の digest 照合と同じ考え方

## 影響

- workspace の配置に `keymap.<name>.yaml` と `mac-keyboard.<layout>.<name>.yaml` が加わる。
  `WorkspaceFileStore` に `listFiles` と `remove` が増え、サーバーの workspace API に `list` と `remove` が増える
- サーバーが root 直下で触れてよいファイルは、適用対象と保持と旧名の Mac 設定になる
- 保持したファイルは Git 管理対象に入る。Cornix の保持は definition の digest を一緒に持つので、
  definition が変わると保持側も読めなくなる。これは `keymap.yaml` と同じ振る舞いである
- 名前の変更は持たない。必要になったら `save` と `delete` で行う
