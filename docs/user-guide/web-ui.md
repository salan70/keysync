# Web UI の使い方

Web UI は、`KEYSYNC_WORKSPACE` で指定した workspace の設定をブラウザで編集するツールです。
ファイルの読み書きは `just ui` が起動したローカルサーバーが行います。
設定やバックアップを外部サーバへ送信することはありません。

起動は clone したリポジトリで `just ui` を実行します。
Web UI をビルドしてから <http://127.0.0.1:5178/> で配信し、Chrome で開きます。
ターミナルは開いたままにし、終了するときは Ctrl+C を押します。
port 5178 が使用中なら起動しません。すでに起動していれば、その URL を開いてください。

開くと workspace の設定が自動で読み込まれます。フォルダを選ぶ操作はありません。
`keymap.yaml` が無くても開け、Mac キーボードだけを編集できます。
別の場所の設定を開くときは、`KEYSYNC_WORKSPACE` を変えて起動し直します。
`KEYSYNC_WORKSPACE` が未設定なら、`just ui` は起動せずに止まります。

## 画面の構成

| 場所                       | 内容                                                                |
| -------------------------- | ------------------------------------------------------------------- |
| 画面上部（ヘッダー）       | 編集対象、Cornix LP の接続状態、テーマ                              |
| 左端の入口                 | `割り当て` `全体` `動作` `検証` `実機` `ファイル`                   |
| 中央                       | layer の切替、盤面、keycode picker                                  |
| 右側（編集パネル）         | 選択中のキー、picker の適用先、動作、raw keycode と表示名、保存状態 |
| 画面下部（ステータスバー） | 診断の件数、保存状態と保存先、通知、実機との差分、`実機へ Apply…`   |

`全体` `動作` `検証` `実機` `ファイル` は画面中央のパネルで開きます。
パネルは `全画面で表示` で広げられ、全画面にしたパネルは次も全画面で開きます。
Esc、`閉じる`、パネルの外側のクリックで閉じると、開いた入口へ戻ります。
Mac を編集しているときは `全体` と `動作` は使えず、入口が淡色になります。

## 編集対象

ヘッダーの `Cornix LP` `Mac ANSI` `Mac JIS` で編集対象を選びます。
左右の矢印キーでも切り替えられます。
各対象の左の印は読み込み状態を表します。

| 印       | 状態                                         |
| -------- | -------------------------------------------- |
| 塗りの丸 | 読み込み済み                                 |
| 輪       | ファイルが無い                               |
| 四角     | 移行が必要（旧 binding、改名前の `cornix/`） |
| 菱形     | 読み込みに失敗した                           |

kanata へ適用できるのは、`Mac ANSI` と `Mac JIS` のうちこのマシンの内蔵配列と同じものだけです。

## キーの割り当て（Cornix）

1. 盤面上のキーまたはエンコーダーをクリックして選択します。
2. 編集パネルの `picker の適用先` で、`キー全体`、`Tap`、`Hold` のいずれかを選びます。
3. 盤面の下の keycode picker から選ぶと、すぐに `keymap.yaml` へ保存されます。
4. 編集パネルの下と画面下部に `ローカル保存済み` と保存先が表示されることを確認します。

picker は `基本` `レイヤー` `メディア・マウス` `特殊` のタブで切り替えます。
`レイヤー` タブでは `MO(n)` `TG(n)` などを layer 番号ごとに選べます。
`Hold` では modifier と `MO(n)` だけを選べます。
`Hold` で `MO(n)` を選ぶと、押している間は layer n、タップでは今のキーになる `LTn(…)` になります。
picker にない keycode（`QK_BOOT` などの危険なキーを含む）は、編集パネルの `raw keycode・表示名` を開いて入力し、Enter または `反映` で保存します。
raw keycode には任意の表示名を設定できます。
表示名は `keysync/labels.yaml` に保存され、実機への書き込み内容には影響しません。

盤面では矢印キーで隣のキーへ移り、Enter で編集パネルへ、編集パネルで Esc を押すと盤面へ戻ります。
layer は盤面の上の `L0` `L1` … で切り替えます。
参照元の無い layer は畳まれていて、`参照なし N 件を表示` で表示できます。
layer を切り替えても選択中の位置は変わらないので、同じ位置を layer ごとに続けて割り当てられます。

ここでの保存はローカルの workspace への保存です。
実機への反映は、別の操作の `実機へ Apply…` で行います。

## 全体（全体マップ）

レイヤー間の参照関係と使用中の Tap Dance を見渡します。

- 各 layer のカードの入力欄で layer 名を編集できます。Enter で保存し、Esc で取り消します。
- `開く` で、その layer を盤面に表示します。
- 参照元の一覧にカーソルを合わせると、参照元のキーが強調されます。押すと参照元の layer を開きます。
- `参照なしの layer も表示` で、通常は隠している layer を確認できます。
- 盤面で選択中の layer を SVG または PDF で `keysync/generated/` へ書き出せます。

## 動作（動作定義）

Tap Dance、Combo、各種詳細設定を編集します。

- 値は Enter を押すか、入力欄から離れたときに保存されます。
- Tap Dance の timeout や設定値は 0〜65535 の整数値です。
- 範囲外の値は保存されず、入力欄の下と画面下部に理由が表示されます。
- 出力が `KC_NO` の Combo は畳まれています。

## 検証

診断と参照の整合を確認します。

- 診断は code ごとにまとめられ、`エラー` `警告` `情報` で絞り込めます。
- `layer N / row R col C へ` を押すと、パネルが閉じて盤面の該当するキーが選択されます。
- Cornix では、Tap Dance や Macro の使用状況と、到達できない layer を確認できます。
- Mac では、ファイル、物理配列、適用先、`device_if` 相当の識別子、件数を確認できます。検出した内蔵配列は出しません。

画面下部の診断件数を押しても、その重要度で絞り込んだ検証が開きます。

## 実機（実機と適用）

Cornix LP では、次の 3 段階を上から順に進めます。

1. `接続（機器を選ぶ）` で Cornix LP へ接続します。
2. `実機から読み込む` で実機の設定を読み込みます。読み込み中は往復回数が表示されます。
3. 差分を確認し、`実機へ Apply…` を押します。

接続しただけでは実機設定を読み込みません。
差分を確認するには、接続後に `実機から読み込む` を実行してください。
読み込んだ後は、実機と workspace の UID と definition が一致しているかが表示されます。

`backup から復元` は、最新のバックアップを画面の編集内容へ読み戻します。
この時点では実機にも `keymap.yaml` にも書き込みません。

Mac を編集しているときは、`kanata へ適用…`、適用先、`kanata の設定を書き出す` が表示されます。
`kanata の設定を書き出す` は `keysync/generated/kanata.kbd` へ書き出すだけで、kanata が読む設定ファイルには触れません。

## ファイル

- `VIL 読込…` は `.vil` を編集内容へ取り込み、`keymap.yaml` へ保存します。実機には書き込みません。
- `VIL 書出` は編集内容を `keysync/generated/keymap.vil` へ書き出します。
- `再読込` はディスク上の設定ファイルを読み直します。
- `表示` でアイコンの見た目を `凹みあり`（既定）と `凹みなし` から選べます。選択はこのブラウザに保存されます。
- `Web UI の使い方` は本ドキュメントを別タブで開きます。

`keymap.yaml` が無い、または読めないときは VIL 読込・書出と backup からの復元は使えません。
再読込は workspace が開いていれば使えます。

## Mac キーボード

選んだ配列の `mac-keyboard.<layout>.yaml` を編集します。
ファイルが無ければ、盤面の位置に表示される `mac-keyboard.<layout>.yaml を作成` で初期ファイルを作れます。
旧名 `mac-keyboard.yaml` は、中の `layout` 宣言が一致すれば読めます。

- 割り当ての無いキーは、layer 0 では入力をそのまま通す「素通し」になり、破線で囲まれます。
- layer 1 以上で割り当ての無いキーは「割り当てなし」になり、押しても何も出ません。layer 0 の割り当てへは落ちません。
- kanata で表現できない割り当て（`TG(n)` など）は picker で選べません。
- 動作の種類は basic、mod-tap、layer switch、none です。
- 編集パネルの `割り当てを外す` で割り当てを消せます。
- 適用先は内蔵キーボードだけです。`実機` パネルに表示されます。

Mac の設定ファイルは workspace 直下に置きます。

### kanata へ適用する

初めて適用する Mac では、先に [CLI の初回の準備](./cli.md#初回の準備) を済ませます。

1. ヘッダーでこのマシンの内蔵配列（`Mac ANSI` または `Mac JIS`）を選びます。
2. 画面下部の `kanata へ適用…` を押します。
3. 差分を確かめ、`適用` を押します。

適用すると、次をまとめて行います。

- 現在の kanata の設定ファイルを `keysync/backups/kanata-<時刻>.kbd` へ退避する
- 設定ファイルを書き換え、読み直して一致を確かめる
- 常駐している kanata に設定を読み直させる

差分が無ければ「このマシンは最新」と表示され、`適用` は押せません。
別のマシンで編集した設定は、`git pull` してから Web UI で適用します。

`kanata へ適用…` を押せないときは、ボタンの右に理由が表示されます。

| 表示                           | 対処                                                                |
| ------------------------------ | ------------------------------------------------------------------- |
| サーバーに接続できない         | `just ui` で起動し直します。                                        |
| この Mac の配列を検出できない  | CLI で `--layout ansi` または `--layout jis` を指定して適用します。 |
| この Mac は ANSI（または JIS） | 表示された配列の Mac で適用します。                                 |
| 設定ファイルを読み込めていない | `ファイル` の `再読込` を押します。                                 |
| 保存中… / 保存できていない     | 保存が終わるのを待つか、保存の失敗を解消します。                    |
| error があるため適用できない   | 検証パネルで error を直します。                                     |

適用のダイアログで止まったときは、kanata の設定ファイルには触れていません。

| 表示                        | 対処                                              |
| --------------------------- | ------------------------------------------------- |
| 画面の内容と … の内容が違う | 保存が終わっているか確かめ、`再読込` を押します。 |
| kanata が見つからない       | `brew install --HEAD kanata` で入れます。         |
| kanata --check が通らない   | 表示された kanata の出力を確かめます。            |

「画面の内容と … の内容が違う」は、外部エディタや `git pull` でファイルを書き換えた後にも出ます。

ダイアログに「kanata が常駐していない」と出たときは、適用しても設定はまだ効きません。
ターミナルで `just mac service install` を実行して登録します。

読み直しだけが失敗したときは、書き込みは完了しています。
`/var/log/keysync-kanata.log` で kanata のログを確かめます。
元に戻す手順は [Safe Apply と復旧](./safe-apply.md#macbook-内蔵キーボードの-apply) にあります。

ターミナルからは [CLI の mac コマンド](./cli.md#macbook-内蔵キーボード管理mac) でも適用できます。

## 診断と差分の確認

画面下部のステータスバーには、いま選んでいる対象の診断が常に表示されます。

Cornix 表示中は次を出します。

- **エラー**: Apply を開始できません。設定の修正が必要です。
- **警告**: Apply の確認で内容ごとに承認が必要です。設定が変わると再確認が求められます。
- **実機との差分**: 最後に読み込んだ実機と workspace の差分件数です。
- `実機へ Apply…` を開始できないときは、ボタンの右に理由が表示されます。

Mac 表示中は次を出します。

- 保存先は `mac-keyboard.<layout>.yaml` です。
- `kanata へ適用…` と、押せないときの理由を出します。
- Vial の差分件数と Apply は出しません。

## 外部エディタとの併用

Web UI は外部エディタによるファイルの変更を検知します。
競合が検知された場合、外部の変更を上書きしません。
編集パネルの保存状態に「外部で変更されたため保存できない」と表示され、未保存の編集は失われます。

1. 外部エディタ側の変更を保存します。
2. Web UI で作業中だった内容を控えます。
3. 編集パネルの `ディスクから再読込`、または `ファイル` の `再読込` を押し、ディスク上の最新状態を取り込みます。
4. 必要な変更を改めて Web UI で編集します。
