# トラブルシューティング

問題が発生したときは、画面下部の状態、診断コード、画面上部のビルド SHA を確認してください。
実機操作で問題が起きたときは推測で操作を続けず、再接続と再読み込みを行ってください。

## 実機接続のトラブル

### Safari や Firefox を使っている

- **原因**: Safari と Firefox は WebHID API に非対応です。
- **対処**: Chrome または Chromium で Web UI を開いてください。

### Cornix LP が一覧に出ない

- **原因**: 接続不良、未給電、または非対応ファームウェアの可能性があります。
- **対処**:
  1. USB ケーブルまたは BLE の接続と給電を確認します。
  2. Vial protocol に対応したファームウェアであることを確認します。
  3. Web UI の左端の `実機` を開き、`接続（機器を選ぶ）` を再度選びます。
  4. 以前の接続が残っている場合は、一度切断してから接続し直します。
  5. Linux では udev rule が要ります。[Linux（Omarchy）で使う](./linux.md#cornix-lp-を-web-ui-から使う) の手順で置きます。

### 接続後も差分が 0 件のまま

- **原因**: `接続（機器を選ぶ）` は接続を開くだけで、設定の読み取りを行いません。
- **対処**: 接続後に `実機` の `実機から読み込む` を実行して最新状態を取得してください。

## Workspace のトラブル

### ローカルサーバーに接続できない

- **原因**: `just ui` のサーバーが止まっているか、別の方法で配信したページを開いています。
- **対処**: リポジトリで `just ui` を実行し、<http://127.0.0.1:5178/> を開いて `もう一度開く` を押します。

「サーバーが古い可能性がある」と出たときは、更新前に起動したサーバーが動いています。
起動中のターミナルで Ctrl+C を押して止め、`just ui` で起動し直します。

### `KEYSYNC_WORKSPACE が未設定` と表示される

- **原因**: 設定を置くディレクトリが指定されていません。
- **対処**: シェルの設定で `KEYSYNC_WORKSPACE` を export し、新しいターミナルで起動し直します。

### `keymap.yaml` が無いと表示される

- **原因**: workspace に Cornix LP の設定ファイルがありません。
- **対処**:
  - 新規作成の場合: `実機 read で workspace を作成` を選びます。
  - 既存の設定がある場合: `just ui` のターミナルに表示される workspace の path が正しいか確認します。`KEYSYNC_WORKSPACE` が意図したディレクトリを指しているかも確認します。

### definition の digest またはパスが一致しない

- **原因**: `keymap.yaml` の参照先定義と実際のファイル内容が一致していません。
- **対処**:
  1. Git で `keymap.yaml` と `keysync/definitions/` の履歴を確認します。
  2. 競合解消で誤った digest を手動入力していないか確認します。
  3. 正しいコミットへ戻してから再読込します。

## 編集・保存のトラブル

### 外部変更との競合が表示される

- **原因**: Web UI で開いている最中に、外部ツール等で同一ファイルが変更されました。
- **対処**:
  1. 外部エディタの変更内容を保存します。
  2. Web UI の未保存内容を退避します。
  3. 編集パネルの `ディスクから再読込`、または `ファイル` の `再読込` を押してディスク上の変更を取り込みます。
  4. 必要な編集を Web UI でやり直します。

### 入力した値が保存されない

- **原因**: 入力値が許容範囲外（0〜65535 以外の数値や構文不正）です。
- **対処**: 入力欄の下と画面下部に表示されるエラーメッセージを確認し、値を修正してください。

## Apply のトラブル

### `実機へ Apply…` が無効

- **原因**: 以下のいずれかの条件を満たしていません。
  - workspace が開かれていない
  - 実機に接続されていない
  - 今回のセッションで読み取りが完了していない
  - 実機との差分が 0 件である
  - エラー（error）がある
- **対処**: ボタンの横に表示される理由を確認します。未接続や未読み込みなら、`実機` で接続し、`実機から読み込む` を実行してください。

### エラー（error）が表示されている

- **原因**: 整合性エラーまたは UID / definition の不一致があります。
- **対処**: `検証` と `実機` パネルで原因を確認し、設定を修正してください。エラーがある状態では書き込めません。

### 承認した警告が再度表示される

- **原因**: 設定や差分が変化したため、以前の承認が無効化されました。
- **対処**: 変化した差分内容を確認し、問題がなければ再度承認してください。

### Apply が中断またはタイムアウトした

- **原因**: 途中で通信が切断されたか、書き込み後の検証に失敗しました。
- **対処**:
  1. 実機を再接続します。
  2. `実機から読み込む` で最初から状態を取得し直します。
  3. 再計算された差分を確認し、改めて Apply します。

## バックアップと生成物のトラブル

### ファイルが見つからない

- **バックアップ**: `keysync/backups/` 配下に保存されます。最新は `latest.vil` です。
- **Web UI の生成物**: `keysync/generated/` 配下に保存されます。
- **CLI の生成物**: `--out` で指定したパスに保存されます。

これらは成果物のため、通常は Git 管理しません。

## CLI のトラブル

### CLI コマンドが失敗する

- **原因**: オプションの指定漏れや、Nix 外の Node.js 実行が原因です。
- **対処**:
  1. `just keysync <subcommand>` の形式で実行しているか確認します。
  2. workspace（`$KEYSYNC_WORKSPACE`、`--workspace` を付けたらそのパス）に `keymap.yaml` が存在するか確認します。
  3. `diff` コマンドに `--against` を指定しているか確認します。
  4. direnv 済みシェルまたは `nix develop` 内で実行してください。
