# 打鍵テストで mod-tap の閾値を実測しながら調整する

2026-09-27。
利用者から、色々な閾値を試せる場所がほしいと要望があった。
指定のキーを打たせ、その結果に応じて調整していく形である。
利用者は、方式として実測を、課題としてロール集と自由入力を選んだ。
計画は plan mode で承認を得た。

## Fact

- ブラウザの `keydown` は Karabiner が処理した後のイベントで、押下時間は観測できない。
- Web UI は、scratchpad へ複製した workspace で Vite の dev サーバーを起動し、headless Chrome（CDP の `Input.dispatchKeyEvent`）で確認した。
  - `⌥A` `⌃A` `⌘A` を混ぜた打鍵は、`ka` `ha` `ja` の組の誤爆 3 件と採点された。
  - 入力欄で Esc を押してもパネルは閉じなかった。
  - `⌘A` でページの全選択は起きなかった。
  - hold 課題（F → ⌘U を 3 回）では、閾値に届かなかった 1 回が外れとして数えられた。
  - パネルから「Karabiner へ適用…」を開くと、パネルの上に適用ダイアログが重なった。
  - 利用者の Karabiner にはすでに 200ms の設定が入っており、計画は「差分なし」だった。これにより「効いている閾値」が確かめ済みになった。
  - 状態文の長さが変わっても、カードの高さは変わらなかった。
- 最初の版では、途中で Enter を押すと未入力の残りが全部「消えた」として数えられた。末尾の脱落を数えない規則を足して直した。
- 利用者の workspace と Karabiner の設定は変えていない。

## Decision

ADR 0045 に記録した。
Rail の入口のアイコンは外部で描く運用のため、keymap のアイコンを借りた。

## Open Question

- 専用アイコンを uiux-numa で描くか。
